# 博客前端 UI 改版方案

## 1. 改版目标

将当前“功能完整、视觉偏默认 Material”的界面，升级为一套有个人辨识度的编辑型博客体验：

- 公共阅读区：温暖、安静、具有内容杂志感。
- AI 助手：轻量科技感，但不抢夺个人介绍的主角位置。
- 个人中心：清晰、可信、便于维护资料和互动记录。
- 管理后台：高信息密度、强可扫描性，和公共博客视觉适度区分。
- 全端一致：桌面、平板、移动端使用同一套设计语言，而不是简单缩放。

设计关键词：`温暖编辑感`、`克制科技感`、`留白`、`内容优先`、`柔和层次`。

## 2. 当前界面评估

### 2.1 做得较好的部分

- 已采用 Material 3、亮暗主题、8 点间距和语义化色彩基础。
- 首页、列表和友链已经支持响应式网格。
- 桌面使用侧边导航，移动使用底部导航，整体路由结构清晰。
- 内容卡片、筛选、AI 对话、后台模块的功能骨架完整。

### 2.2 主要问题

1. 页面内容几乎铺满可用宽度，缺少统一的阅读容器，桌面端视觉重心过散。
2. 所有区域都依赖相似的描边卡片，层级主要靠边框表达，页面显得平且重复。
3. 左侧导航只有图标、标签和头像，缺少品牌信息、分组和登录状态表达。
4. 首页首屏是传统大图轮播，品牌介绍、内容推荐和个人气质之间联系较弱。
5. 内容筛选全部平铺，首屏被控件占据，用户需要先“看表单”才能“看内容”。
6. “关于我”页面的个人介绍只有两行，AI 聊天卡片反而占据绝大部分空间。
7. 友链页数据少时大片空白，没有形成“朋友网络”或社区氛围。
8. 登录页是孤立表单卡片，缺少品牌故事、信任说明和模式切换的视觉反馈。
9. 管理后台使用 11 个横向 Tab，信息架构拥挤，模块切换和当前位置不够清晰。
10. 移动首页内容卡片存在底部溢出，说明固定宽高比不适合不同文字长度。

## 3. 设计方向

### 3.1 核心风格

采用“自然纸张 + 森林青绿 + 暖金点缀”的编辑型风格：

- 自然纸张色降低纯白背景的工具感。
- 青绿色延续现有品牌，承担导航、链接、选中态和主要操作。
- 暖金仅用于精选、置顶、重要数字和轻量强调。
- 内容图片保留自然色，不叠加强品牌滤镜。
- 阴影只在浮层、悬停和关键卡片使用，普通内容靠留白与色块分层。

### 3.2 视觉层级

页面只保留三种主要容器：

- `Page Canvas`：全局背景，不加边框。
- `Section Surface`：大区块的轻微色差背景，可无边框。
- `Interactive Card`：可点击内容，使用细边框和悬停反馈。

避免每个模块都套 Card。标题、正文、元数据、操作区应更多通过字号、间距和对齐建立层级。

## 4. 设计系统

### 4.1 配色

#### 浅色主题

| Token | 建议色值 | 用途 |
| --- | --- | --- |
| `primary` | `#27665A` | 品牌、主按钮、选中态 |
| `primaryContainer` | `#DCECE6` | 选中背景、轻提示 |
| `secondary` | `#B77924` | 精选、数据强调 |
| `background` | `#F5F3ED` | 页面纸张背景 |
| `surface` | `#FCFBF8` | 主要内容区 |
| `surfaceMuted` | `#EEEDE7` | 筛选区、次级区块 |
| `textPrimary` | `#18201D` | 标题与正文 |
| `textSecondary` | `#65706B` | 摘要与元数据 |
| `border` | `#D9DDD8` | 必要描边 |
| `error` | `#BA3A3A` | 错误和危险操作 |

#### 深色主题

| Token | 建议色值 | 用途 |
| --- | --- | --- |
| `primary` | `#78B7A7` | 品牌、主按钮、链接 |
| `primaryContainer` | `#254A42` | 选中背景 |
| `secondary` | `#E5B86A` | 精选与数据强调 |
| `background` | `#111614` | 页面背景 |
| `surface` | `#181E1B` | 内容区 |
| `surfaceMuted` | `#202824` | 次级区块 |
| `textPrimary` | `#EDF2EF` | 标题与正文 |
| `textSecondary` | `#AAB5B0` | 摘要与元数据 |
| `border` | `#34403B` | 必要描边 |

当前深色主题的青绿色偏暗，文字和操作控件的辨识度不足。深色模式应提高主色明度，避免直接复用浅色主色。

### 4.2 字体

- 中文正文：优先系统中文字体栈，正式发布时可内置 `Noto Sans SC`。
- 内容标题：可使用 `Noto Serif SC`，增强博客和编辑感。
- 英文与数字：`Inter` 或系统字体。
- 代码块：`JetBrains Mono`。

建议层级：

- 首页主标题：40/48，700。
- 页面标题：30/38，700。
- 区域标题：22/30，700。
- 卡片标题：17/24，650。
- 正文：16/28，400。
- 元数据：13/20，500。

正文阅读宽度控制在 `680-760px`，避免长行影响阅读。

### 4.3 圆角与阴影

- 小控件：8px。
- 输入框、按钮：10px。
- 内容卡片：14px。
- Hero 和大区块：20px。
- 对话框：20px。

普通卡片默认无阴影；桌面悬停时增加轻阴影和 `translateY(-2px)`，时长 180ms。

### 4.4 间距与容器

- 全局仍使用 8 点网格。
- 移动页边距：16px。
- 平板页边距：24px。
- 桌面页边距：32-48px。
- 公共页面最大宽度：1240px。
- 文章正文最大宽度：760px。
- 管理后台最大宽度：1440px，允许更高信息密度。

建议新增统一组件：

- `AppPageContainer`
- `SectionHeader`
- `BlogCard`
- `MetaRow`
- `EmptyState`
- `LoadingSkeleton`
- `AdaptiveScaffold`

## 5. 全局布局改造

### 5.1 桌面公共页面

将当前窄 NavigationRail 改为 220-240px 的品牌侧栏：

- 顶部：头像、博客名、短签名。
- 中部：推荐、全部内容、朋友、关于。
- 底部：主题切换、登录或个人中心。
- 选中项使用柔和色块，不使用过重的胶囊背景。
- 侧栏可在 900-1100px 区间收缩为图标模式。

主内容统一进入最大宽度容器，不再从侧栏后一直铺到屏幕边缘。

### 5.2 移动公共页面

- 底部导航保留 4 个一级入口：推荐、内容、朋友、关于。
- 登录后头像放入顶部操作区，进入个人中心。
- 管理后台不进入公共底部导航，从头像菜单或个人中心进入。
- 底部导航使用安全区和轻微浮层色差，避免压住页面内容。
- 列表与卡片不再使用固定 `childAspectRatio`，改为内容驱动高度。

### 5.3 页面顶部

公共页面使用两类顶部：

- 首页：品牌型 Hero，不重复显示普通 AppBar 标题。
- 内页：紧凑标题栏，包含页面标题、简短说明和右侧操作。

滚动后标题栏可轻微收缩并增加背景模糊，避免大面积固定 AppBar。

## 6. 页面级改造

### 6.1 首页

首屏从单纯轮播改成“个人品牌 Hero + 精选内容”双栏布局：

- 左侧：一句个人定位、简短说明、两个操作按钮。
- 右侧：一张精选内容大卡，保留封面图和摘要。
- 移动端改为上下排列。

内容区调整：

1. `最近更新`：一张横向主卡 + 其余两张紧凑卡。
2. `热门文章`：排名式列表，突出标题、阅读量、点赞量。
3. `最近照片`：图片内容使用不规则但克制的画廊布局。
4. 页面底部加入简短个人签名和“去关于我”入口。

轮播若保留，应增加页码和自动播放暂停规则；更建议改成静态精选，减少首屏运动干扰。

### 6.2 全部内容

将筛选区改成两级结构：

- 首行：搜索框、排序、筛选按钮。
- 展开筛选面板：类型、标签、日期。

优化规则：

- 默认只显示搜索与已选筛选摘要。
- 标签过多时使用横向滚动或“更多标签”，不全部换行。
- 已选条件显示为可删除 Chip，并提供“清空筛选”。
- 桌面列表可使用“封面 200px + 正文 + 元数据”的编辑型横卡。
- 移动端封面宽度降到 120-132px，标题最多两行，标签最多显示两个。
- 加载使用骨架屏，避免整页居中的转圈。

### 6.3 内容详情

- Hero 封面不直接承担全部标题信息，标题、摘要、日期、阅读量放入独立文章头部。
- 文章正文居中为 720px 左右，图片可扩展到 920px。
- 桌面右侧可增加文章目录、阅读进度和分享操作。
- 点赞改为正文底部的明确反馈组件，点击后有轻量缩放和状态动画。
- 评论区与正文之间使用大留白和分区标题，不与正文挤在同一视觉层。
- Markdown 统一标题间距、引用、代码块、表格、图片说明样式。

### 6.4 朋友们

- 顶部增加一句说明，例如“这些是在互联网上认真生活的人”。
- 卡片加入站点主色或头像背景色，减少空头像时的重复感。
- 桌面端卡片可采用横向名片：头像、名称、简介、访问按钮。
- 悬停时显示“访问站点”，外链图标不再始终抢占视觉焦点。
- 数据较少时使用居中的 2-3 列布局，而不是从左侧开始留下大片空白。

### 6.5 关于我与 AI 助手

页面改成桌面双栏：

- 左栏 36%：个人头像、简介、技术栈、经历、联系方式。
- 右栏 64%：AI 助手。

移动端按“个人介绍 -> 技术栈 -> AI 助手”排列。

AI 区域优化：

- 空状态展示 3-4 个示例问题按钮。
- 消息气泡区分用户和助手，但避免强烈双色对撞。
- 输入栏固定在卡片底部，支持多行输入和快捷发送说明。
- 配额改为轻量进度提示，不放入长副标题。
- 历史会话在桌面使用侧抽屉，在移动端使用底部弹层。

### 6.6 登录与注册

桌面改为左右分栏：

- 左侧：博客品牌、简短介绍、精选图片或柔和抽象背景。
- 右侧：登录注册表单。

交互优化：

- 登录/注册使用顶部 Segmented Control，避免底部文字链接切换。
- 密码支持显示/隐藏。
- 表单错误在字段下方就地提示，SnackBar 只用于全局错误。
- GitHub 登录与邮箱登录之间增加“或”分隔。
- 提交按钮保持稳定高度，加载时不要改变布局。
- 移动端去掉外围 Card，让表单自然铺在页面中。

### 6.7 个人中心

- 顶部增加个人资料摘要：头像、昵称、邮箱、角色和资料完整度。
- 桌面使用左侧二级导航：个人资料、账号安全、账号绑定、我的互动。
- 移动端使用可滚动 Tab 或分组列表。
- 表单按卡片分成“公开资料”“账号安全”“第三方账号”，避免长表单连续堆叠。
- 保存操作在内容修改后才激活，并提示未保存状态。

### 6.8 管理后台

后台与公共导航分离，使用标准管理布局：

- 左侧后台菜单：概览、内容、互动、用户、AI、系统。
- 二级菜单承载评论、点赞、浏览、知识库、日志等模块。
- 顶部栏显示当前位置、全局搜索、刷新和用户菜单。
- 不再使用 11 个横向 Tab。

概览页：

- 指标卡增加图标、环比或辅助说明，不只展示数字。
- 增加最近内容、待处理评论、最近登录或系统状态区域。
- 模块入口应可点击并切换对应页面。

数据列表：

- 桌面使用表格或高密度列表。
- 移动端降级为信息卡片。
- 工具栏统一搜索、筛选、批量操作、新建按钮。
- 状态颜色保持语义一致：成功绿、草稿金、危险红、普通灰。

## 7. 交互与动效

### 7.1 基础反馈

- 可点击卡片：180ms，轻微上移和边框变色。
- 按钮：按下缩放至 0.98，100-140ms。
- 页面内容切换：淡入和 8px 位移，200-240ms。
- 筛选面板：高度和透明度动画，220ms。
- 点赞：图标缩放和颜色变化，250ms。
- 新消息：淡入，不对整个列表做复杂动画。

### 7.2 状态设计

每个数据页面统一提供：

- 骨架加载。
- 空状态插图或图标、说明和主要操作。
- 内联错误和重试。
- 操作成功反馈。
- 删除、解绑等危险操作确认。

所有动效应遵循系统“减少动态效果”设置。

## 8. 响应式规则

| 范围 | 布局策略 |
| --- | --- |
| `< 600px` | 单列、底部导航、16px 页边距 |
| `600-899px` | 单列或双列、紧凑侧栏/底部导航、24px 页边距 |
| `900-1199px` | 可收缩品牌侧栏、主内容 2 列 |
| `>= 1200px` | 完整品牌侧栏、最大宽度容器、首页 3 列 |

重要原则：

- 不用固定卡片宽高比承载可变文本。
- 文章正文与后台表格使用不同最大宽度。
- 移动端至少预留 80px 底部空间，避免底部导航遮挡。
- 所有可点击目标不小于 44x44px。

## 9. 可访问性

- 正文与背景对比度达到 WCAG AA。
- 图标按钮必须有 Tooltip 和 Semantics。
- 焦点态不能只靠颜色，应增加 2px 外轮廓。
- 支持键盘遍历、Enter 激活和 Escape 关闭弹层。
- 图片补充语义说明；装饰图排除语义树。
- 支持 200% 文本缩放，不出现截断和溢出。
- 不使用颜色作为状态的唯一表达方式。

## 10. 实施顺序

### P0：建立统一基础

1. 重构颜色、文字、圆角、阴影和内容宽度 Token。
2. 新增 `AppPageContainer`、统一 Section Header、卡片和状态组件。
3. 重构公共响应式 Shell 与导航。
4. 修复移动首页卡片溢出。

### P1：公共核心体验

1. 首页 Hero 与内容卡片。
2. 全部内容的折叠筛选和响应式列表。
3. 内容详情的文章阅读布局。
4. 登录注册页面。

### P2：品牌与互动

1. 关于我和 AI 双栏。
2. 朋友页。
3. 个人中心。
4. 骨架屏、空状态、悬停和页面转场。

### P3：管理后台

1. 后台独立 Shell 和分组侧栏。
2. 概览指标与快捷入口。
3. 各管理列表的工具栏、表格和移动端卡片。
4. 编辑对话框和 Markdown 编辑器统一视觉。

## 11. 验收标准

- 桌面公共页面内容宽度稳定，超宽屏不再横向发散。
- 首页首屏同时表达“我是谁”和“推荐读什么”。
- 移动首页不出现任何 RenderFlex overflow。
- 内容列表首屏筛选控件高度减少至少 35%。
- 文章正文行宽保持在 45-80 个中文字符的舒适范围。
- 关于我页面中个人信息不再被 AI 卡片压缩成两行。
- 后台任意模块最多通过两级导航到达，不使用超长 TabBar。
- 亮暗主题均通过正文和控件对比度检查。
- 键盘可完成导航、筛选、登录和对话框操作。

## 12. 建议优先落地的首批页面

第一轮建议只改 4 个位置，以最小成本建立完整设计语言：

1. 全局主题与公共 Shell。
2. 首页。
3. 全部内容。
4. 登录页。

这四处覆盖品牌、导航、卡片、搜索筛选、表单和响应式布局。完成后再复用组件改造详情、关于、个人中心和后台，能显著减少重复返工。
